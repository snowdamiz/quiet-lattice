FINDINGS

F1. A symlink at the runtime path is left live.
Severity: blocking for this publisher contract.
File: packages/tools/blender/t08/export_saved.py:50-53.
Reachable from export_one whenever packages/client/public/models/<family>/<stem>.glb is a symlink. The real caller is export_saved.py, which run.py does not wrap.
What happens: is_symlink() raises before any archive or unlink. binding.json is FAILED with "runtime path is an unexpected symlink; refusing alias mutation". previous.glb is absent. The symlink stays. Writing the link target after that failure changes the bytes the runtime path serves. Reproduced as symlink_dst_left_live: returned false, liveIsSymlink true, liveReads MUTATED-AFTER-FAIL.
Fix: if the runtime path is a symlink, copy the target bytes into the attempt as a regular nlink-1 previous.glb when the target is a regular file, then unlink the symlink itself before the child. Do not leave the alias in place. If the target cannot be read, still unlink the symlink and record the read error on the FAILED binding. Do not resolve the path and write through it.

F2. A GLB that cannot be read is not removed, and the error escapes the publish of one stem.
Severity: blocking.
File: packages/tools/blender/t08/export_saved.py:54-58 and 94-98.
Reachable from export_one on any PermissionError or other OSError from read_bytes, both for a pre-existing runtime GLB and for a GLB the child has just written.
What happens: the handler's dst.read_bytes() runs before dst.unlink(). If that read raises, finally still writes binding.json and then the exception leaves export_one, so a multi-stem batch stops. Reproduced:
  unreadable_existing_glb: thrown PermissionError errno 13, binding FAILED, runtime bytes still CURRENT-GLB, previous null, names [binding.json].
  unreadable_new_glb_left_in_place: same throw, runtime bytes NEW-UNREADABLE, previous CURRENT-GLB, the new mode-000 file was not unlinked.
Fix: quarantine with os.replace of the directory entry, which moves a mode-000 inode without reading it. On any failure path, unlink the runtime path in a finally that does not read it. Catch errors inside the except handler so they are stored on the binding and do not escape export_one. Re-hash the source immediately before status is set to PASS.

F3. SIGTERM drops the runner receipt and leaves the child.
Severity: blocking.
File: packages/tools/blender/t08/run.py:125-132 and 147-170. There is no signal handler. The child is started with start_new_session=True, so it is not in the runner's process group.
Reachable when a watchdog, the lock owner, or an operator sends SIGTERM to the runner. export_one unlinks the old GLB before it starts run.py, so a dead runner can leave the child to write the runtime path with nobody left to validate it. That composition was read from the two functions. It was not executed as a Blender export into the repo.
What happens: default SIGTERM does not run finally. Reproduced as sigterm_runner: runnerExit -15, receipt false, markerWritten true, marker WROTE. The child survived the parent.
Fix: handle SIGTERM and SIGINT by setting a flag, or catch them and fall into the existing cleanup. Track the child process group in export_one and reap it if the runner does not return. Always write result.json.

F4. killpg is outside the cleanup try, so one OSError loses the receipt.
Severity: blocking.
File: packages/tools/blender/t08/run.py:152, and the SIGKILL call at line 158 is in the same unguarded sequence. result.json is written only after both calls, at line 170.
Reachable when killpg raises. A normal SIGINT did not: sigint_runner wrote a receipt, exit recorded -15, pass false, remaining group empty, and the child was reaped. The KeyboardInterrupt is the sleep at line 146, after finally has started. An injected PermissionError at the real killpg call did fail: killpg_permissionerror, runnerExit 1, receipt false, sleeper still alive (pid 75908 at the time; the harness later confirmed no review process left).
Fix: put killpg and the SIGKILL fallback in try/except for ProcessLookupError and PermissionError. Record the error on the receipt. Write result.json in a nested try so a cleanup error cannot skip it.
