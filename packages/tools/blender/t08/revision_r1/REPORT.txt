DECISIONS:
  Who may publish after a failed cleanup? → only the supervisor → producer paths
    remain private even when killpg is denied and a surviving child later finishes.
  How to archive unreadable current output? → retire directory entry first and
    preserve inode/error facts → content permission is not removal authority.
  How to preserve readable alias history? → exclusive independent regular copy,
    fsync, no shared inode → mutations cannot rewrite recorded historical bytes.
  Is signal delivery itself proof of termination? → no → wait the actual child,
    observe its group, preserve uncertainty and block reuse if unresolved.
  What if a canonical rename is physically denied? → record invalidated=false,
    canonicalAbsent=false and launch no producer → never claim impossible removal.
  What if an atomic receipt write reports an error after installing PASS? → retire
    that uncommitted receipt and write FAILED/fallback → no false current PASS.
  What if signal arrives during the final receipt write? → check after the write,
    retire uncommitted PASS and invalidate output → process and failure facts agree.
  How to prove caller reachability without forbidden art tools? → unchanged stock
    code plus inert CPU dependency fixtures and barriers → real publication paths,
    explicitly no claim about geometry/codec execution.
