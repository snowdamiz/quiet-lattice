**R5-1 — P2: metadata replacement can block in open before descriptor/type validation**

Location: `packages/tools/src/capture/fauna_packet/caller.py:69`, between the pathname `lstat`/regular-file check at 65–68 and descriptor checks at 70–72. Reachable for predecessor result at 317, predecessor consumption at 318, and root grant at 382.

`Path.open('rb')` is a blocking open. If the pathname changes from the checked regular file to a FIFO after `lstat` but before the real open, opening its read end waits for a writer. The following `fstat` cannot execute. Admission has no active phase timer: capture/cleanup deadlines begin only in `run_unit`, after `consume` returns. The maximum+1 payload read and size/hash checks are never reached.

Independent reproduction, repeated for result, consumption and grant:

1. Create a new inert Git fixture and run the actual first caller as an isolated pinned-Python subprocess. Parent observes OS exit 0 and builds the next synthetic grant from that exit and actual receipt hashes.
2. Run actual second `main -> consume` with native/decoder ports forbidden.
3. A deterministic hook immediately before the real `Path.open` renames the checked regular metadata file to a preserved sibling and puts an actual filesystem FIFO at that pathname. The caller's real `lstat` has already completed; its real `open` then blocks.
4. A harness-only 250 ms SIGALRM interrupts the wait. Recorded traces terminate in caller.py:69 -> pathlib.open -> io.open. In all three cases the timer was `(0.0, 0.0)` before the harness armed its cutoff, there were zero payload reads, zero helper/decoder calls and no successor consumption/output/evidence allocation.

The harness cutoff is not a caller refusal or a production timeout. Without external intervention, a FIFO without a writer has no reason to return. A preexisting FIFO is promptly refused, isolating the gap to the check/open interval. Replacing the file with a different regular inode is also correctly refused before payload reads.

Evidence: `fresh-boundaries.py`, `fresh-boundaries-results.json` (three `fifo-before-open` rows including full traces and retained fixtures), `fifo-controls.py`, `fifo-controls-results.json`. Both commands exit 0 because their assertions confirm the described behavior; **that is a successful defect reproduction, not a candidate PASS**.

Correction: obtain the descriptor with nonblocking/no-follow flags appropriate to the pinned platform (for example `os.open` with `O_RDONLY | O_NONBLOCK | O_NOFOLLOW`), then validate its regular type, identity and size before wrapping/reading it. Preserve the single snapshot, original caps and digest semantics. The small FIFO primitive control confirms a nonblocking descriptor can be obtained and rejected by type without waiting; it is not a patched-caller qualification. No repository code was changed.

This finding concerns a replacement **before a snapshot exists**. It does not require preventing filesystem changes after completed admission, and does not claim false-success admission or native allocation occurred in the FIFO case.
