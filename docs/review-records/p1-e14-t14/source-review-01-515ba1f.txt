## What the change does

`colorMask` is set only on creatures and flora (`families.json` lines 261 and 280). `material_set` passes masks only when `model.mode == "export"` and the family has `colorMask` (`checks.py:322`). Otherwise `MaterialInfo` is one-argument.

`_imported_color_masks` (`checks.py:280–296`) keeps a mask only when every render-mesh user of that material has `active_color == color_attributes[0]`, `render_color_index == 0`, and `_color_mask_problem` is None. Any miss returns `()` and the special path stays off. Colliders and `REF_*` stay outside `render_meshes`, which is the existing render-mesh set the task asked for.

`_masked_image` (`materials.py:84–113`) then requires an unmuted, unclamped `ShaderNodeMix` with `data_type == RGBA`, `blend_type == MULTIPLY`, the enabled RGBA result connected to Principled Base Color, and the Factor socket enabled, unlinked, and exactly `1.0`. Both enabled RGBA inputs must be linked. One side must be an unmuted `TEX_IMAGE` Color output; `trace` on that socket (no masks) still applies the old coordinate and image rules. The other side must be an unmuted Vertex Color Color output. An empty `layer_name` is accepted, matching the importer, which leaves the name empty so the rendered attribute is used. A non-empty name must equal the active attribute name on every collected user. It is not a string allowlist.

`trace(socket, color_masks=())` (`materials.py:117`) returns the masked image only when that helper matches; otherwise the old classifier runs. `MaterialInfo` forwards masks for `baseColor` only (`materials.py:207`). Bake, export planning, and `textures()` still call `MaterialInfo(m)` with no masks.

The 95% / 0.05 sum rule in `_color_mask_problem` (`checks.py:167–181`) is unchanged.
