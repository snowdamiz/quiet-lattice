F1 — P2 — Retirement can pass without live enemy/observer positive controls.
Location: packages/tools/src/smoke/symbiotic-online.spec.ts:443-456, particularly :445; combat acceptance at :412 also permits hp=0.
The retirement predicate requires net.joined and entities.has(enemy), but never inspects the enemy's hp/mode, nor requires the observer's own entity to remain present/alive. Net.joined is connection state, not character survival. The production combat owner intentionally leaves a killed creature as hp=0/mode=dead for DEATH_BEAT_S=3 (packages/server/src/combat/zone.ts:48,730-735). Therefore enemy membership is not an alive control. A kill after the combat screenshot freeze is thawed, before owner close reaches the server, can leave the corpse present when the removal predicate passes. The camera-ray and targetGone checks concern only the companion and do not repair this.
Reproduction: controls.test.mjs:110 extracts and evaluates the exact source template predicate. With joined=true, owner/companion absent, no remote/drawn companion, enemy={hp:0,mode:'dead'}, and no observer entity, it returns true; the required rejection fails. The living enemy/observer positive control passes. This is a CPU falsification of the assertion, not a fabricated live snapshot or a claim that this sequence occurred in a browser.
Correction: after a fresh post-disconnect snapshot require the exact observer entity to remain the expected live player in the arena and the enemy to be a live mob with hp>0/mode!='dead'. Record these states and snapshot tick in evidence; keep the real source-attributed hit + reduced HP check and ensure 0<hp<baseline before releasing the owner. Never satisfy survival by healing, respawning or rewriting snapshots.

F2 — P2 — Teardown loses primary and secondary failures.
Locations: packages/tools/src/smoke/online.ts:154-158 and :216-218.
When startup fails, catch awaits stop() before throwing err. If server termination or Vite cleanup rejects, stop's rejection replaces the startup error. Additionally, Promise.allSettled attempts both existing owned stops, but the following loop throws only the first rejected reason, discarding any second failure. The existing worker route/import tests do not exercise these cases.
Reproductions against the actual imported startOnline, with only external OS/service APIs replaced by inert in-memory adapters:
- createVite rejects with 'primary Vite startup failure'; server SIGTERM throws 'server TERM failure'. The caller receives only the latter, without cause/errors retaining the primary.
- Once started, Vite.close and server SIGTERM both reject. Both stop calls are attempted, but the caller receives only the Vite error.
Both required error-preservation assertions fail. A control verifies an asynchronous Vite close rejection does not prevent attempted server termination.
Correction: collect all stop failures, and preserve the startup error plus cleanup errors using an AggregateError/cause structure. Do not catch-and-ignore failures or let cleanup replace the body/setup error. Preserve borrowed namespace ownership.
Classification: setup catch masking is inherited from the shared harness; discarding additional allSettled failures is in the new stop implementation. Both remain reachable from this new fixture and violate the brief's failure-preservation requirement.

F3 — P2 — A created Vite handle is not owned until after listen succeeds.
Location: packages/tools/src/smoke/online.ts:185-192, especially :191-192.
createVite returns v, then await v.listen() precedes vite=v. If listen rejects (including the free-port/strict-port race), catch calls stop while vite is still null. The created server's close method is never attempted; the fixture's online variable is also never assigned, so its afterAll cannot recover the handle. The server subprocess does get a stop attempt.
Reproduction: actual startOnline with createVite returning a handle whose listen rejects 'listen EADDRINUSE'. The primary listen error is propagated and SIGTERM is attempted, but closeVite is absent. The required close assertion fails.
Reachability verified in installed Vite 8.3.5 source: listen awaits startServer without failure cleanup; strict-port httpServerStart rejects when binding returns EADDRINUSE. These are external-boundary controls, not an actual port/server run.
Correction: assign the returned Vite handle to the owned variable immediately after createVite resolves, before awaiting listen. Close it on every subsequent failure and retain all resulting errors per F2.
Classification: retained pre-existing harness defect, not claimed to be introduced by 55f357cf. It directly violates the new fixture's promised all-owned-stops failure boundary. An outer process supervisor is containment, not evidence that this owned stop was attempted.
