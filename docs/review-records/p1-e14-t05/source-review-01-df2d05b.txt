FINDINGS

R1 — P1 — CPU cancellation releases the lane before its child is reaped.
packages/tools/blender/flora/run_cpu.py:64-78 (especially 66 and 75).
SIGTERM has no handler; process termination skips finally. The child was started in a new session and survives, while the kernel releases the wrapper's flock. A second SIGINT during the cleanup wait also escapes it; that wait catches only TimeoutExpired.
Actual repro, independently rerun with real processes and a fake Python workload in place of Blender:
  single SIGINT: exit 124, child dead, lock reusable, EXIT receipt present;
  timeout: exit 124, child dead, lock reusable, EXIT receipt present;
  SIGTERM: exit -15, child ALIVE, lock reusable, no EXIT receipt;
  second SIGINT after child acknowledges cleanup TERM: exit -2, child ALIVE, lock reusable, no EXIT receipt.
Impact: a second CPU run can start while the previous owned workload still runs/writes.
Minimal fix: handle catchable termination signals, defer repeated interruption during process-group terminate/escalate/reap, write a terminal result, then release ownership. Do not claim SIGKILL can be caught. Cover both failure cases alongside the passing single-interrupt/timeout controls.
Evidence: helper-repro/runner_results.json; helper-repro/sigterm/driver.log; helper-repro/double_sigint/driver.log. All fake process groups were cleaned up by the harness.

R2 — P2 — a rejected lock contender destroys the incumbent's log.
packages/tools/blender/flora/run_cpu.py:52-53.

Minimal fix: acquire lane ownership before touching the log, then exclusively create a unique attempt log or reject an existing destination. Preserve older completed logs as well.
Evidence: helper-repro/runner_results.json and helper-repro/lock_contention/contender.log.
