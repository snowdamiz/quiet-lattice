If cleanup is the only failure it is thrown unchanged; if both cleanup operations fail after success, the first cleanup is cause. All entries, including undefined, are retained by identity. No error message/properties/facts are normalized, serialized, cloned, or mutated.
- Where to establish UI logged-error failure? -> Immediately after its existing work loop, inside try before cleanup. This changes failure preservation only; successful frame/render/output work stays in its prior order.
- Small shared helper? -> One private finishCapture function within capture.ts, strictly limited to these two resources and their existing cleanup order.
