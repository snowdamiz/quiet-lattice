QUANTIZATION AND THE FALSE DENSITY METHOD
All 2,539 POSITION accessors are signed short (5122), normalized true. Sampled node scales are uniform. The anchor blade node scale is 24 and its raw short span is the full −32767..32767 axis, so a normalized read is 48 m on that axis. That matches the reported 48 m blade. Treating those shorts as floats and then applying the same node scale stretches that axis by 32,767, to about 786 km. That is the discarded Lark/Props failure mode.
decode_meshopt.mjs reads positions, normals, and UVs with accessor.getElement. gltf-transform 4.5.1 getElement decodes normalized integers (short / 32767, unsigned short / 65535) and returns floats unchanged. density.py then multiplies by the node world matrix from getWorldMatrix. The matrix algebra matches a column-major glTF matrix times the local point. Y-up is left unconverted there; a pure axis swap does not change the Jacobian singular values. audit.py raw_geometry uses the same dequantized positions and then the Blender Z-up map (x, −z, y).
Render LOD rows in density-all-d10.json record UV type [5126, false] on all 156 asset/LOD rows. That is float, unnormalized. The 1,311 normalized unsigned-short UV accessors are the collider primitives (1,340 COL meshes minus 29 COL meshes with no UV). The density walker never enters those nodes, because their ancestors are not LOD nodes. Collider UVs are outside this density result.
gltf-transform quantize skips TEXCOORD when any value lies outside [0,1] and leaves it float. Charts shifted by a whole integer therefore stay float. In-range charts become normalized unsigned short. getElement handles both. The render set measured here is the float set.
