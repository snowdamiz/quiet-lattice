Impact/rule: the bounded serial CPU lane and unresolved-cohort exclusion contract
are broken exactly when failure evidence cannot be durably recorded. A still-live
Blender/codec cohort in production can overlap the next heavy export, exceeding
the task's admitted capacity. The receipt honestly reports the old failure, but
it is not consulted on the next admission. No corrupted canonical bytes, native
render failure or performance measurement is claimed from this CPU fixture.

Concrete correction: establish an exclusive persistent ownership marker before
launching any producer, and refuse admission if it cannot be installed. Keep it
through errors and unresolved cleanup; clear it only after the actual child is
reaped and the cohort is verified empty. Treat incomplete/pending marker state as
uncertain too. Do not rely on successfully creating the only guard after cleanup
has already failed. Add a real-caller case for marker persistence failure and a
retry while the old producer is held behind a barrier.
